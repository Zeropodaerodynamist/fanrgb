# Changelog

All notable changes to FanRGB are documented in this file. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html) as `0.MINOR.PATCH` until the chip and fan-role model is
stable: MINOR = behaviour users notice (modes, defaults, new pages), PATCH = fixes and threshold tuning. Error codes
(`FRG-Exxx`) are part of the public surface and are never renumbered.

## [0.2.0] - unreleased

### Added

- Fan-mode tiles: Silent, Balanced, Performance, Full speed, Auto (AI), BIOS, plus Custom profiles.
  Alt+1..6, Ctrl+Shift+M and a tray "Fan mode" submenu.
- Fan header roles (CPU, radiator, case fans, AIO pump, unknown, unused), set in "What's connected?".
- "Identify your fans" wizard: tests each header and asks what changed; a possible pump spends at most 20 s
  below 60 %; stops on heat or alarms (FRG-E209).
- AIO pump headers get their own CPU-temperature curves, run by the fan chip: flat and quiet through idle and
  light load (Silent 35 %, Balanced 45 %, Performance 65 %), steep under sustained load, 100 % by 84-86 °C, never
  below 30 %; Auto (AI) uses the Balanced pump curve; Full speed 100 %. (An earlier 0.2 build ran pumps flat at
  70/85/100 %, louder than the BIOS at idle.) Unknown headers get a 60 % floor and no AI.
- Headers without a speed signal (e.g. a pump on CPU_FAN) show their speed in %, never an rpm.
- Case-fan chip curves get a GPU-temperature floor, reprogrammed in 5 % steps only.
- Fan hysteresis is written to the chip, so it also applies to chip-run curves.
- FRG-E305 "CPU cooling may have failed": watches tach-less CPU fan/pump headers.
- FRG-E309 cooling-efficacy monitor with a learned baseline per duty/power band.
- Hang watchdog: no engine heartbeat for 30 s returns all fans to the BIOS.
- CPU safety card (Hot / Watch / No sensor) and "Running, no speed signal" state for tach-less fans.
- Tray balloon notifications for critical alerts and sensor loss, rate-limited; toggle in Settings > Safety.
- Per-zone colour correction (gamma, R/G/B gain), applied to LED output only, never to previews.
- Colour calibration tab: guided white balance and fan-vs-pump match; test colours end after 60 s idle and the
  saved lighting always returns.
- LED segments (up to 8 per ARGB header) with their own gain, for a pump head chained behind fans.
- Windows Dynamic Lighting detection, banner and "Let FanRGB control these LEDs" (FRG-E409, FRG-E410).
- Signed self-update from the FanRGB GitHub repository: minisign manifest, SHA-256 and PE checks,
  anti-downgrade, 60 s health probation and automatic rollback (FRG-E700 to E715). The daily check needs no
  GitHub account or token; a read-only access token is optional, for a private repository or a higher rate limit.
- Updates page (Ctrl+8), update banner and sidebar badge.
- Driver inventory and opt-in daily Windows Update driver check; FanRGB never installs drivers (FRG-E720 to E726).
- Signed vendor driver list: latest Intel Arc, AMD chipset and Realtek LAN versions (FRG-E727 to E729).
- Redesigned UI: lit render of the rig on Overview, board texture, Lighting tabs, new app and tray icon.
- Diagnostics report: git version, Windows build, per-channel role/mode/failsafe, RGB, Dynamic Lighting,
  conflicting software, cooling notes, recent log lines.
- BIOS-controlled fans show an estimated duty from the firmware curve.
- `fanrgb --revert` (elevated): goes back to `fanrgb.exe.old` with fans on BIOS during the swap, verifies the exe
  and keeps the anti-downgrade state consistent.
- `fanrgb --reset-update-state` (elevated; asks for confirmation unless `--yes`).
- `tools/release.ps1` tags the exact pushed, CI-green commit (`--target <sha>`), refuses a dirty tree, unpushed
  HEAD or version mismatch; `-Prerelease` (default on) and `-PromoteLatest <tag>`.
- GitHub Actions CI: fmt, clippy, tests, cargo-audit, cargo-deny, release build + PDB; SBOM, cargo-auditable,
  provenance on tags. `rust-toolchain.toml` pins Rust 1.91.1.
- `docs/RELEASING.md`, `docs/KEYS.md`, `docs/BUILDS.md`.
- Settings › About › Licences shows every licence text that comes with `fanrgb.exe`: NOTICE, Apache-2.0,
  MPL-2.0 (with a link to the source code), LGPL-2.1 for the PawnIO modules, the font and HIDAPI licences and the
  Rust crates' licences (`THIRD-PARTY-LICENSES.txt`, generated by cargo-about from `about-text.hbs`).
- `tools/release.ps1` attaches `LICENSE`, `LICENSE-MPL-2.0`, `NOTICE`, `THIRD-PARTY-LICENSES.html`/`.txt` and
  `licenses/` to every GitHub release. Release builds (`release.ps1`, `dist.ps1`) use `--remap-path-prefix`, so
  the exe carries no local folder names.

### Changed

- Non-BIOS fan modes need one "Identify your fans" run: until every present, controllable header has a confirmed
  role, all headers stay on the BIOS, tiles say "Identify fans first" and choosing a mode opens Identify.
- FRG-E309 is inform-only: alert and tray balloon, no forced 100 %. FRG-E305 and FRG-E301 still force.
- FRG-E305 forces every CPU-chain header to 100 %, including fans with a tach.
- Thermal safety margins live in one module (`src/control/limits.rs`); values unchanged.
- The BIOS mode always leaves every fan to the BIOS; stored overrides are kept but ignored.
- Empty headers (not present, never spinning, not configured) are no longer taken over.
- A chip curve is used only when its single source is CPU temperature; other curves run in software and keep
  the chip's CPU failsafe.
- Calibration needs a fan confirmed as CPU, radiator or case fan; refused for pump/unknown and during alarms.
- "Unused" stops driving a header but keeps it in the cooling-failure watch.
- Existing lighting gets gamma 2.2, so mixed colours shift toward the screen colour (gamma 1.0 = raw, like GCC).
- Effect brightness and fades are linear before gamma (a 50 % slider gave about 3.5 % light).

### Fixed

- Intel Arc GPU power is read as milliwatts (was taken as percent; bad AI input and FRG-E304 noise).
- Colour-order override now applies to static colours, sync and hardware effects.
- An AIO pump could run at about 28 % under Balanced.
- `--diag` showed an unused 85 °C failsafe and a failsafe on uncontrolled channels.
- One tach-less fan no longer blanks the AI airflow estimate for its whole group.
- The critical-temperature banner states the real release point (critical - 5 °C, not - 8 °C).
- Role floors apply at once; the wizard test duty ends on a wall-clock deadline.
- Engine panics are contained: wizard and calibration stop, fans are released; BIOS mode stops the wizard.
- Stable FRG-E309 baseline key, no learning while forced to 100 %.
- A critical alert that recurs within 15 min is still notified.
- Heartbeat and slow scans moved off the engine thread: no false hang trips or FRG-E206.
- Updater: version recorded only once healthy, clean exit is not a failure, installs only the
  release shown (FRG-E713), refuses an insecure state folder (FRG-E712).
- Calibration lights and saves segments by LED range, one 1024-LED bound.
- Closing the Identify wizard always cancels it; tray mode changes are not undone by a pending edit.
- Driver check "Checking..." always ends.
- Idle tray CPU from 0.35 % to 0.19 % of a core (Dynamic Lighting monitor no longer polls; hidden window sleeps).
- Tests use per-process temp folders, so parallel runs no longer interfere.

### Security

- Dynamic Lighting reads and writes the desktop user's registry hive, not the elevated one.
- Driver check: report read and deleted through one checked handle, helper in a kill-on-close job,
  helper text stripped of control, bidi and zero-width characters.
- Update and driver helpers run unelevated and refuse elevation; the elevated app re-verifies all staged files.
- Updater: repository pinned by id, TLS 1.2+, allow-listed redirects, WinHTTP options fail closed,
  token buffers wiped, `status.json` untrusted.
- Update token is DPAPI-encrypted per user and redacted from logs, diagnostics and errors.
- Release keys must be password-protected (`protect-keys`, `sign --require-encrypted`); dry runs use a throwaway
  key. Catalog and release keys are separate and never cross.
- Independent pre-publication security audit (2026-11-11; 48 findings, none Critical or High; summary in
  `docs/SECURITY-AUDIT.md`). Fixed in this release:
  - A minimum cooling no setting can switch off: from 12 °C below the critical temperature every fan FanRGB
    drives rises to at least 75 % at 2 °C below it, also when the fan chip runs the curve itself (the floor is
    merged into the chip curve, so it holds if the app hangs) (FR-CTL-001).
  - The board's CPU headers keep 20 % and its PUMP header 30 %, with no fan stop, whatever role the settings
    file gives them (FR-PRIV-005).
  - Fan calibration tables are range-checked like the calibration wizard checks them (no flat or inverted
    table, `max_rpm` must match the measurements, a speed plateau maps to its highest duty); a lost CPU
    temperature hands every software-driven fan back to the BIOS; calibration needs a CPU temperature; a
    tick that panics every time no longer takes and releases the fans in a loop; the RGB command byte is
    bounded (FR-CTL-002 to FR-CTL-006).
  - Chip curves with points less than 1 °C apart are fitted correctly; crash-snapshot values, chip curves and
    driver-call sizes are checked before use; configuration mode is always left on error (FR-HW-001 to 005).
  - The running-program check no longer takes its parameters from the file it judges; "Open Task Manager"
    starts it without administrator rights; state-folder recovery never rewrites a file found in its place;
    diagnostics hide the Windows account name and SID (FR-PRIV-001 to 004).
  - Updater and catalogue: WinHTTP options fail closed, classic (write-capable) tokens are refused, elevated
    reads use identification-level impersonation, the catalogue fetcher caps decompressed size, and the
    rollback note in `docs/RELEASING.md` is corrected (FR-UPD-002, 003, 005 to 007).
  - The embedded PawnIO modules are checked byte-identical to the official 0.2.11 release, and their LGPL
    source now ships with every download (`assets/pawnio/source`, FR-PUB-010).

### Removed

- Diagnostics "Drivers" card (moved to the Updates page) and the flat tray profile list.

### Data formats

- `config.json`: new fields (`fan_roles`, per-zone `correction` and `segments`, `rgb.dither` (opt-in), `drivers`,
  `updates`, `general.notifications`). Lenient loading: v0.1 configs load, a bad value resets only itself.
- New: `update_state.json` (admin-only), `cooling_baseline.json`, `driver_check.json`,
  `driver_catalog_state.json`, `update_token.bin` (per user).
- No `min_version` needed: nothing changed incompatibly.

## [0.1.0] - unreleased

Initial version (commit `fb15a63`), never published as a release.

- Fan control for Gigabyte ITE Super I/O boards via PawnIO: BIOS, Fixed, Curve and AI modes, profiles,
  calibration, curves run in the chip with a chip-level CPU failsafe.
- Learning "AI" thermal controller (grey-box model, predictive control, safety floor, FRG-E502 distrust).
